🎯 Goal
Build the “AI Meal Plan” feature on the dashboard for our Meal Planner App (React 18 + TS, Wouter, TanStack Query, Tailwind, Radix if helpful). 
Connect to our FastAPI backend at http://localhost:8000 and show a full 7-day plan with per-meal regenerate + complete toggles.

📡 Backend Endpoints (FastAPI)
Base URL: http://localhost:8000

1) POST /ai/meal-plans/generate
Request body:
{
  "profile": { /* full user profile object from DB (see type below) */ },
  "days": 7,                     // 1–14 allowed
  "mealsPerDay": 5,              // 3 or 5
  "provider": "openai",          // keep as "openai"
  "model": "gpt-4.1-mini"        // optional; default OK
}

Response body:
{
  "success": true,
  "plan": {
    "days": [
      {
        "date": "YYYY-MM-DD",
        "meals": [
          {
            "slot": "breakfast" | "lunch" | "dinner" | "snack1" | "snack2",
            "title": "string",
            "calories": number,
            "macros": { "protein": number, "carbs": number, "fat": number },
            "ingredients": ["string", ...],
            "instructions": "string",
            "allergen_flags": ["string", ...],
            "cuisine": "string",
            "prep_time_min": number
          }
        ],
        "total_calories": number
      }
    ],
    "metadata": {
      "diet": "string",
      "calorie_target": number,
      "meals_per_day": 3 | 5,
      "provider": "openai",
      "model": "auto" | "string"
    }
  }
}

2) POST /ai/meal-plans/regenerate
Request body:
{
  "profile": { /* same profile object */ },
  "provider": "openai",
  "model": "gpt-4.1-mini",
  "day": "YYYY-MM-DD",
  "slot": "breakfast" | "lunch" | "dinner" | "snack1" | "snack2",
  "constraints": { /* optional e.g. calorie_range, avoid, keep_cuisine, prep_time_max_min */ },
  "context_meals_for_that_day": [ /* the other meals for that day to keep calories balanced */ ]
}

Response body:
{
  "success": true,
  "meal": {
    "slot": "...",
    "title": "...",
    "calories": number,
    "macros": { "protein": number, "carbs": number, "fat": number },
    "ingredients": ["..."],
    "instructions": "...",
    "allergen_flags": ["..."],
    "cuisine": "...",
    "prep_time_min": number
  }
}

🧾 Frontend Types (create a shared types file)
export type Profile = {
  user_id: string;
  full_name?: string;
  date_of_birth?: string;
  gender?: 'male' | 'female' | 'other';
  height?: number; // cm
  weight?: number; // kg
  activity_level?: 'sedentary' | 'lightly_active' | 'active' | 'very_active';
  fitness_goal?: 'lose_weight' | 'maintain' | 'build_muscle';
  target_weight?: number;
  daily_calorie_goal?: number;
  diet_type?: 'none' | 'vegetarian' | 'vegan' | 'keto' | 'paleo' | 'mediterranean';
  allergies?: string[];
  disliked_foods?: string;
  preferred_cuisines?: string[];
  meals_per_day?: '3_meals' | '3_meals_2_snacks';
  intermittent_fasting?: boolean;
  breakfast_time?: string;
  lunch_time?: string;
  dinner_time?: string;
  chronic_conditions?: string[];
  supplements_taken?: string;
  stress_level?: 'low' | 'medium' | 'high';
  sleep_duration?: number;
  water_intake_goal?: number;
  // legacy fields can exist but not required by UI
};

export type Meal = {
  slot: 'breakfast' | 'lunch' | 'dinner' | 'snack1' | 'snack2';
  title: string;
  calories: number;
  macros: { protein: number; carbs: number; fat: number };
  ingredients: string[];
  instructions: string;
  allergen_flags?: string[];
  cuisine?: string;
  prep_time_min?: number;
};

export type DayPlan = {
  date: string;
  meals: Meal[];
  total_calories?: number;
};

export type Plan = {
  days: DayPlan[];
  metadata: {
    diet?: string;
    calorie_target?: number;
    meals_per_day: 3 | 5;
    provider: string;
    model: string;
  };
};

🧠 Data Sources (assume we already have these)
- A function getUserProfile(userId: string): Promise<Profile> that reads from our frontend-managed DB.
- A function persistPlan(userId: string, plan: Plan): Promise<void> to save the returned plan to our DB.
(If not present, generate stub implementations that we can later connect.)

🔌 API Client (create /lib/mealPlanApi.ts)
- create functions:
  - generatePlan(profile: Profile, days = 7, mealsPerDay = 5): Promise<Plan>
    -> POST /ai/meal-plans/generate with the body above; return data.plan
  - regenerateMeal(args: { profile: Profile; day: string; slot: Meal['slot']; constraints?: Record<string, any>; contextMeals: Meal[] }): Promise<Meal>
    -> POST /ai/meal-plans/regenerate; return data.meal

⚓ Hooks (create /hooks/useMealPlan.ts)
- useMealPlan(userId: string)
  - state: plan (Plan | null), status, progress (0–100), error
  - actions:
    - loadExistingPlan(): loads last saved plan for the user (optional stub)
    - generate(days: 7 | 14, mealsPerDay: 3 | 5):
        1) fetch profile via getUserProfile(userId)
        2) call generatePlan(profile, days, mealsPerDay)
        3) set plan in state
        4) persistPlan(userId, plan)
        5) show toast "Meal plan generated"
    - regenerate(day: string, slot: Meal['slot'], constraints?: Record<string, any>):
        1) collect other meals for that day as context
        2) call regenerateMeal({ profile, day, slot, constraints, contextMeals })
        3) replace that slot in local plan state
        4) persistPlan(userId, updatedPlan)
        5) show toast "Meal updated"

  - Use TanStack Query for mutations + caching; expose query keys like ['meal-plan', userId].

🖥️ UI (Wouter route + components)
- Route: /dashboard/meal-plan
- Components to create:
  1) <MealPlanDashboard />
     - Header with "Generate Meal Plan" button and a selector for (days: 7/14, mealsPerDay: 3/5).
     - When generating, show a progress indicator + skeletons.
     - Render each Day as a collapsible section (Accordion) with total calories.
  2) <MealDay />
     - Displays date + total_calories
     - Maps meals → MealCard
  3) <MealCard />
     - Shows title, calories, macros, ingredients, instructions
     - Buttons: "Complete" (toggle state & persist), "Regenerate"
     - On Regenerate: opens a small dialog to set optional constraints:
       - calorie_range (min/max)
       - keep_cuisine (select)
       - avoid (comma-separated)
       - prep_time_max_min (number)
     - After regenerate returns, swap in the new meal and toast success.

🎨 UX details
- Mobile-first layout; collapsible days, sticky Generate bar at top.
- Tailwind + Radix UI for Accordion/Dialog/Toast.
- Show small badges for cuisine and prep_time_min.
- Completed meals get a subtle checkmark and dim style.

🧪 Edge cases
- If backend returns 422 (validation), show a friendly error toast.
- If backend 502/429, retry button on the banner.
- If plan exists, ask “Overwrite existing plan?” before generating.
